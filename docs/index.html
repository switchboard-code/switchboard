Switchboard — a coding agent for your terminal The model is
a slot.

Line up the models you already have — a small local one, a bigger one, a paid API, the subscription you pay for anyway. Switchboard routes every turn to the cheapest one that can actually do the work, and climbs only when the work proves harder.

Other agents ask you to pick one model up front, then spend it on everything — reading a file and redesigning a module at the same price. Switchboard treats the model as a slot your ladder fills, checks the real request before each turn, and shows the reason for every move. /why answers the question every other tool leaves you asking.

01Field test · 16 Aug 2026 · public journal

Same tasks. Same judge.
Very different bills.

Eleven seeded coding tasks, one attempt each, run headless under one verifier: Switchboard, Claude Code, and Codex CLI. All three solved all eleven. What differed was what the identical outcomes cost.

ToolSolvedThe bill
Claude Code 11 / 11 $22.35 metered API spend, frontier model throughout
Codex CLI 11 / 11 641,576 tokens of gpt-5.6-sol plan quota
Switchboard 11 / 11 $0 4 tasks entirely on free local rungs · the rest on plan quota

The ladder is the interesting column: Switchboard bought a frontier rung only where its own escalation evidence said the cheap one was stuck. Eleven times out of eleven, paying frontier price bought nothing the verifier could see. One corpus, one machine, one day — the full run, the raw journal, and the eval gate are public, and the numbers are held in place by tests, not by memory.

02How it works

Cheapest rung first.
Climb on evidence.

01

Line up your models

Cheapest at the bottom: a small local model, a bigger local one, a paid API, the subscription you already have. Four lines of TOML a rung. Your mix, your order, your ceiling.

02

Every turn gets routed

Before each turn, Switchboard measures the request that would actually be sent — its size, the tools it needs, what’s reachable, what’s warm in cache, what fits your budget — and picks the lowest rung that qualifies. Not vibes: the request itself.

03

It climbs on evidence, and says why

Stuck in a tool loop, fresh test failures, a model hedging — signals like these can move the turn upward between rounds, never mid-answer. Every move shows its reason in the transcript. /t3 pins a rung by hand; /tier auto hands routing back.

03The receipts

Every session is a record.
Ask it questions.

Everything the agent does is appended to a session log — every call, every dollar, every diff. That turns the questions you’d normally ask a chat transcript into questions the record can actually answer.

“Why this model?” What was ruled out, why, and what the turn would have cost on every other rung. /why
“What did that cost?” The session bill by turn or by rung. Price the next prompt before you send it. /cost · /estimate
“Which turn wrote this line?” Line provenance replayed from the log. Lines the record can’t explain say so — nothing is guessed. /blame
“When did the tests go red?” Binary-search the session’s turns for the one that broke your verifier, then restore the tree exactly. /bisect
“Was the cheap model enough?” Run one prompt on two rungs, side by side. Keep the winner; a tie means the cheap one sufficed. /race
“Did it do what it claimed?” A second model reads the finished turn and reports where the closing message and the record disagree. /audit
04The workbench

Not a chat log.
A workbench.

The terminal UI handles the navigation work that otherwise sends you back to an editor mid-session:

  • Find and open code with a command palette and revision-checked search — a file that changed under you is refused, not opened stale.
  • Review changes with an exact Git diff and a per-turn view of what the agent actually wrote.
  • Navigate semantics — outline, symbols, definitions, references, diagnostics — through your installed language server.
  • Delegate one level of subagent, up to four in parallel, sharing your permission rules.
  • Extend it with your Claude and Codex skills, plugins, MCP servers, and hooks — under your trust grants, never by default.

The full command surface lives in the session reference.

05Safety & control

Your machine,
your rules.

Approvals

It asks before it acts

Commands run host-direct only after you approve them. Standing rules you write yourself cover what you’ve already decided; a request carrying a credential always comes back to you.

Confinement

A real sandbox when you want one

-sandbox runs commands inside verified macOS Seatbelt or Linux bubblewrap confinement — and reports the boundaries it finds instead of calling them isolation.

Secrets

What leaves is scanned first

Keys live in the OS keychain, prompts are scanned for key-shaped strings before they go out, and external tools are never inside the sandbox’s trust.

Reach

You name the providers

Decide which providers a workspace may reach and everything else is refused before cost is even considered. Local, plan, and dollars are counted separately, everywhere.

The full posture — permissions, trust, credentials, confinement boundaries — is in security.md and sandbox.md.

06Get it

One script.
Then sb.

$ curl -fsSL https://raw.githubusercontent.com/switchboard-code/switchboard/main/install.sh | bash

Checksums verified · installs to ~/.local/bin · or build from source with Go 1.26

The first run opens a setup checklist: which providers it can reach, a masked prompt for any keys, and a pick for the model t1 starts on. It can reuse an existing Codex CLI login. From there, every turn you type gets routed.
